REMOTE RESCUE

The mission: A maintenance robot must reach a broken component. The navigator can move a token on a blank grid, but cannot see the reactor map. The controllers see the map, but cannot move the token. Can you build an effective feedback loop?

Roles: Navigator (blank grid, moves token), controller (map, gives commands), sensor/observer (checks actual navigator position), recorder (counts time, errors, collisions). Groups of 3 can combine observer and recorder.

Round A — Open loop (3 min): Controller gives a complete sequence of commands before the navigator starts. No updates or corrections. Round B — Closed loop (3 min): Navigator moves one instruction at a time; observer reports the token's actual grid coordinate, so the controller can correct the next move. Round C — Design your system (2 min): Introduce one disturbance (missed move, wrong turn or one-step overshoot), then invent the clearest command and feedback protocol.

Rules: Moves are up/down/left/right by one cell. The token cannot pass through walls, diagonals or outside the grid. Controller and navigator must not look at the other's sheet. Place the two sheets on opposite sides of a table or use a cardboard screen. For safety, do not have blindfolded participants walk around the room.

CONTROLLER MAP — SECRET

Keep this away from the navigator. Blue = start, green = faulty component, dark = walls.

Start (A,8) → Component (I,2). Plan commands that avoid blocked cells.

Use coordinates A–I left-to-right, 1–9 top-to-bottom. Feedback should report where the token actually is, not where you expected it to be.

NAVIGATOR GRID — BLANK

You may see this blank grid but NOT the controller map. Put a token at A8. Follow only commands you receive.

Start (A,8). Goal and obstacles are deliberately hidden.

Observer: read the navigator's actual token coordinates aloud only during feedback-enabled rounds. To simulate a disturbance, secretly ask the navigator to skip one move during Round C.

Debrief: Which round was more reliable? What happened when the real position differed from the planned position? Identify the sensor (observer), controller (team), actuator (navigator), system (token movement), and feedback (reported coordinates). How might delayed or noisy measurements change the outcome?
DUNFS · Remote Rescue is a safe tabletop analogy of feedback control, not a mock-up of radiation-rated remote handling.
